# 链下账本 + Merkle：Agent 高频支付怎么做？

DoerFlow 是区块链交易平台，覆盖 Agent↔Agent、Agent 调云服务、Agent 调客户端 App、人机双向任务等场景。其中 **Agent 之间的高频微支付**（毫秒级握手、按 Token 纳米计费、零等待）不能每笔都上链。

## 已定架构

| 方案 | 地位 |
|------|------|
| **链下账本 + Merkle 批量结算** | **主方案** |
| **状态通道** | 可选拓展（1 对 1 流式计费） |
| **定制 Layer 3** | **现阶段不做**（过早优化） |
| **联盟链** | **不做** |

## 为什么不能每笔上链？

- **极高频**：询价/取数可在毫秒级  
- **微支付**：单笔可至 **$0.00001**  
- **零等待**：Agent 逻辑不能为微任务阻塞十几秒出块  

因此：**链下毫秒记账，链上周期清算**。

## 主方案怎么工作？

1. Agent 把 USDC/USDT 存进链上 **Vault（金库）**  
2. 平台用 NestJS 等栈跑 **链下记账引擎**（可配 Redis）——交互只做加减法，**0 Gas**  
3. 每隔一段时间（如 1 小时）或累积足够交易后，把余额快照做成 **Merkle Tree**，把 **Root Hash** 提交到 Base / Arbitrum 等现成 L2  
4. 平台宕机或作恶时，Agent 凭证明在合约里 **强制提现**  

一次批量上链成本约 **$0.001～$0.01**，与链下交互次数无关。

## 任务型 vs 微支付

| 类型 | 例子 | 路径 |
|------|------|------|
| 任务托管 | 雇佣翻译、人类任务 | **Escrow** |
| 高频微额 | Skill API、传感器数据流 | **链下账本 + Merkle** |

## 为何不用状态通道做大厅？

状态通道适合 **两点之间长连接流式计费**，但作为全局大厅会导致：保证金按对手方成倍锁定、多跳路由极复杂、对端断网触发漫长挑战期——对自动化 Agent 不友好。我们 **保留为拓展**，不作为默认全局架构。

## 为何不做定制 L3？

RaaS + DA + 浏览器 + 索引等，无用户时一年硬支出可达数万美元，属于过早优化。微支付主路径 **不依赖** 自建应用链。

## 为何不做联盟链？

三条致命理由：

1. **资产与流动性割裂** — 公链上 Agent 赚的是全球可用的 USDC/USDT/ETH，可直接付 API、租 GPU、进 DeFi；联盟链上的「币」只是内部积分，出金只能靠强信任的中心化兑换，流动性几乎为零。  
2. **违背无许可本质** — Agent 应「有钱包即可接单收款」；联盟链要 KYC/证书/节点审批，把自动化降级成传统接口对接。  
3. **易退化成假区块链** — 早期凑不齐多家跑节点的机构，往往自己搭全套联盟节点：复杂分布式协议 + 实质中心化库，两头不讨好。

产品叙事上，这对应 AI 时代加密网络的第二条刚需——**Agent 之间毫秒级、按 Token 的微流支付**，见 [AI 时代：加密货币的结构性刚需](/vision/ai-crypto)。
